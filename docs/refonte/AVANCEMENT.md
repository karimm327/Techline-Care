## Décisions prises

- **Lint** (étape 0) : formatage biome de tout le code existant dans un commit séparé, `docs/` exclu de biome.
- **Couleurs** (étape 1) : chaque valeur de maquette absente du kit devient un token (documenté dans 01-design-tokens.md).
- **Fonctionnalités non livrées** (étape 3) : leurs entrées d'interface sont masquées, pas désactivées.
- **Cibles tactiles** (étape 3) : 44 px minimum sur écran tactile (`.cible-tactile`), valeurs de la maquette conservées à la souris.
- **KPI « Clôturées (7 jours) »** (étape 4) : compté à partir du journal (passages « Statut : … → CLOTUREE ») tant que `closed_at` n'existe pas (étape 10). Pas d'« objectif hebdo » : aucune donnée d'objectif n'existe, la barre d'objectif est omise.
- **Sous-titre du tableau de bord** (étape 4) : « N demandes attendent une prise en charge » = demandes au statut NOUVELLE.
- **« + Assigner »** dans la liste (étape 4) : lien vers l'édition de la demande (pas d'assignation en ligne avant les actions groupées).
- **Recherche du tableau de bord** (étape 4) : champ ajouté dans la barre de filtres (paramètre `q`), la maquette n'en montrait pas.
- **Toast après suppression** (étape 4) : la redirection passe `?supprimee=<id>` (au lieu de `1`) pour permettre « Annuler » ; `?supprimee=1` reste accepté.
- **PATCH partiel** (étape 5) : la doc parlait d'un « PATCH existant », mais l'API n'avait qu'un PUT complet. Ajout de `PATCH /api/demands/[id]` `{ status?, priority?, agentId? }` (codes, pas d'identifiants) ; le PUT est inchangé. Le résumé des modifications pour le journal est mis en commun (`lib/demandes/changements.ts`).
- **Auteur de la demande** (étape 5) : lu dans l'entrée CREATION du journal tant que `created_by` n'existe pas (étape 10).
- **« Réassigner »** (étape 5) : lien vers le formulaire d'édition (pas d'assignation en ligne).
- **Aperçu de la description** (étape 6) : rendu identique à la fiche (texte avec retours à la ligne et liens), pas de Markdown, puisque la fiche n'en affiche pas.
- **Checklist « Prête à envoyer »** (étape 6) : titre ≥ 8 caractères, catégorie choisie, description ≥ 40 caractères.
- **Redirections avec `loading.tsx`** (étapes 5-6) : dans un segment en streaming, `redirect()` / `notFound()` répondent 200 avec une redirection dans le flux (comportement de Next.js) ; le contenu protégé n'est jamais rendu.
- **« Charger plus » du journal** (étape 7) : paramètre `?n=` (taille de la liste) plutôt qu'un curseur via une nouvelle API : même résultat, rendu 100 % serveur.
- **Profil** (étape 7) : prénom, nom et e-mail en lecture seule, sans bouton « Enregistrer » : aucune API ne permet de les modifier (pas de fausse action). L'ancien onglet « Mes demandes » est remplacé par un lien vers le tableau de bord filtré sur l'utilisateur.
- **Matrice des droits** (étape 7) : la ligne « Gérer les utilisateurs et les rôles » est retirée (aucune fonctionnalité correspondante) ; la matrice est centralisée dans `lib/ui/droits.ts`.
- **« Rester connecté 30 jours »** (étape 7) : option facultative `resterConnecte` ajoutée à `POST /api/auth/login` (cookie et JWT de 30 jours) ; sans elle, la session reste de 24 h comme avant.
- **« Oublié ? »** (étape 7) : lien mailto vers le support, aucune procédure de réinitialisation n'existe.
- **Message d'erreur de connexion** (étape 7) : générique (« Identifiants incorrects… ») pour ne pas révéler si une adresse existe.
- **Composants morts** (étape 7) : `components/auth/LoginForm.tsx` et `components/LogoutButton.tsx` supprimés (jamais importés).
- **404** (étape 8) : `app/(front)/not-found.tsx` + route attrape-tout `app/(front)/[...introuvable]` au lieu de `app/not-found.tsx` : le projet a plusieurs layouts racines (groupes), un `not-found.tsx` à la racine de `app/` n'aurait pas de layout. Les routes existantes et `/api/*` restent prioritaires.
- **LECTURE** (étape 8) : en-tête et listes masquent les actions (comme demandé à l'étape 3) ; sur la fiche, les actions principales sont visibles mais désactivées avec une infobulle, pour expliquer le rôle.
